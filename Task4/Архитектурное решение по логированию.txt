## Мотивация
Сейчас ошибки или нестандартные ситуации разбираются со слов клиента: клиенты рассказывают, как что-то пошло не так. Чтобы понять, что случилось на стороне сервиса, разработчикам и специалистам поддержки требуется очень много времени. Логирование позволит: 
- сократить время, требующееся для разбора проблемного случая
- быстрее определять место возникновения проблемы
- понять, в каком из сервисов на пути оформления заказа возникла проблема
- улучить опыт людей, находящихся на поддержке

## Метрики, на которые повлияет внедрение логирования
Технические: 
- среднее время обнаружения инцидента - внедрение логирования позволит быстрее обнаружить наступление инцидента, не дожидаясь сообщений от партнеров или клиентов 
- среднее время решения инцидента - внедрение логирования позволит быстрее разбираться в сложных ситуациях и определять причину сбоя
- увеличение процента обращений, которые могут быть решены специалистом поддержки без подключения разработчика - внедрение логрования и обучение специалистов позволит проследить путь заказа в разных системах и увидеть, была ли ошибка в каком-то из них

Бизнес-метрики: 
- количество жалоб клиентов и партнеров на потерянные заказы
- среднее время ответа на жалобы клиентов и партнеров
- повышение лояльности и уровня доверия клиентов и партнеров

## Список необходимых логов
Логи необходимо разделять по уровням: Info, Error, при необходимости Debug (на время расследования плавающего бага, например).
Список необходимых логов: 
- timestamp
- service name
- operation name
- total time
- success/error
- error level
- error message
- order id
- partner login

При возникновении большого количества логов с уровнем Error должен срабатывать алерт на команду поддержки.

Поскольку команда не сможет реализовать единовременно логирование и трейсинг всех выделенных для этого систем, в первую очередь необходимо реализовать их для систем, работа которых наиболее критична при оформлении заказа: 
1. MES API - в этой системе производится расчет модели, без которого невозможен старт работы с заказом
2. Messages Queue - очередь сообщений является центральным узлом, через который проходят все обновления статуса заказа
3. Shop API - через эту систему к нам также попадают заказы от клиентов.

## Предлагаемое решение
Для реализации решения предлагается использовать стек ELK. Потребуется доработать сервисы, чтоб они начали логировать события. Каждый из сервисов будет отправлять логи в Filebeat.
В качестве индекса предлагается использовать наименование сервиса, среду выполнения, разделять ежедневно. Также нужно будет настроить ILM: логи уровня Error должны быть доступны минимум месяц, лучше три.

## Аспекты безопасности
Для обеспечения безопасности после внедрения логов необходимо: 
- доступ к логам - внутри компании, логи должны быть недоступны извне
- в логи не должна отправляться чувствительная информация
- партнеры не должны получать информацию из логов
- использовать TLS для всех соединений
- настроить политику хранения логов

В перспективе можно настроить систему анализа логов для выявления подозрительной активности в сервисах.
