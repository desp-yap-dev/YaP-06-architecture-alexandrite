## Мотивация
На текущий момент зачастую происходят ситуации, когда заказ "теряется" или "застревает". Быстро определить, почему и где это происходит, невозможно. Трейсинг позволит: 
- увидеть весь "путь" заказа от момента создания 
- быстрее определять место возникновения проблемы
- получить связь между событиями, происходящими с заказом в разных сервисах

## Метрики, на которые повлияет трейсинг
Технические: 
- среднее время обнаружения инцидента - внедрение трейсинга позволит быстрее обнаружить наступление инцидента, не дожидаясь сообщений от партнеров или клиентов 
- среднее время решения инцидента - внедрение трейсинга позволит быстрее разбираться в сложных ситуациях и определять причину сбоя
- среднее время обработки заказа - внедрение трейсинга позволит видеть узкие места, такие, где сильно теряется производительность

Бизнес-метрики: 
- количество жалоб клиентов и партнеров на потерянные заказы
- среднее время ответа на жалобы клиентов и партнеров
- повышение лояльности и уровня доверия клиентов и партнеров

## Сервисы
Поскольку на данный момент процесс работы с заказом размазан по всем сервисам, для внедрения трейсинга потребуется внести изменения практически в каждый из сервисов IT-ландшафта компании.
Список данных, которые должны попадать в трейсинг: 
- timestamp
- service name
- operation name
- total time
- success/error
- error message
- order id
- previous state
- current state

## Предлагаемое решение
Для реализации решения предлагается использовать связку Open Telemetry + Jaeger UI. Потребуется доработать сервисы, чтоб они начали отправлять требуемую информацию, используя Open Telemetry SDK.

## Компромиссы
MES является системой, купленной у вендора, экспертизы в компании нет. Поэтому доработка сервисов этой системы для внедрения трейсинга на данном этапе может оказаться слишком дорогой. В будущем возможны либо наращивание экспертизы в данном сервисе и его доработка для отправки трейсов, либо доработка общей схемы для возможности горизонтального масштабирования: тогда перед MES будет реализован gateway, на который можно будет возложить обязанности отправки трейсов. 

## Аспекты безопасности
Для обеспечения безопасности после внедрения трейсинга необходимо: 
- доступ к трейсам - только после аутентификации в системе пользователям, у которых есть роль "Поддержка"
- в трейсы не должна отправляться чувствительная информация
- доступа к трейсам не должно быть извне, партнеры не должны получать информацию из трейсов
- использовать TLS для всех соединений
- настроить политику хранения трейсов

## Дополнительное задание
Для реализации автоматического мониторинга и алертинга предлагается добавить связку prometheus + grafana: настроить запросы в jaeger (например, отслеживать заказы, для которых слишком долго не меняется статус) и отображать такие заказы в grafana. Также на ряд таких запросов можно настроить алерты, чтоб команда и лид оперативно узнавали о проблемах.
